## Standing operating instructions

1. **Always load full project context before doing work.** Before any edit, list `src/pages/`, open the relevant `.astro` files, and re-read this CLAUDE.md and `PAGES.xlsx`. Do not rely on assumed state from a prior session — the repo is the source of truth.
2. **`PAGES.xlsx` is the page inventory.** Every page on the site is listed there with its name, URL, status (Live / Draft / Archived), indexing (Indexed / Noindex), layout, and last updated. Update this file whenever a page is added, removed, renamed, or its indexing changes.
3. **`public/sitemap.xml` mirrors the indexed pages from `PAGES.xlsx`.** When a new indexed page ships, add it to the sitemap with today's `<lastmod>`. When a page is removed or switched to noindex, remove it from the sitemap. Never include noindex routes in the sitemap.
4. **Indexing rule.** A page is "indexed" by default. To make a page private, pass `noindex={true}` to `MainLayout` (or add a `<meta name="robots" content="noindex, nofollow" />` if using a different layout). Noindex pages must be excluded from `sitemap.xml` and listed as "Noindex" in `PAGES.xlsx`.
5. **Canonical URLs come from `astro.config.mjs` (`site:`).** Do not hardcode absolute URLs in templates.
6. **American English** in all prose. Compound Health is US-based and serves US clients, so the entire site uses American spelling (optimize, color, personalized, program, advisor). Legal copy already uses US spelling.
7. **No em dashes** in copy.

## Workflow when adding or changing a page

1. Create/modify the `.astro` file under `src/pages/`.
2. Confirm `noindex` is set correctly via the layout prop.
3. Update `PAGES.xlsx`: add the row or update status / indexing / last updated.
4. Update `public/sitemap.xml`:
   - If the page is indexed → add `<url>` entry with absolute URL and today's date in `<lastmod>` (YYYY-MM-DD).
   - If switching to noindex or removing the page → delete its `<url>` entry.
5. Run `npm run build` to confirm the site compiles.
6. Commit with a clear message referencing the page slug.

## Design variations

`/` is the design that ships. Candidate redesigns of the home page live on their own routes, so the live site and every candidate can be opened side by side. This was set up on 2026-09-07, when the Duna-idiom redesign moved off `/` and onto `/v1`. On 2026-09-11 the client delivered their final v1 as one flattened self-contained page and it replaced everything on that route: see the v1 entries under Design system below.

- **`src/data/variants.ts` is the source of truth.** It lists the live design plus every variation, with a label, a route, a one-line note and a status of `ready` or `planned`. The switcher reads it; so do the placeholder pages. Add a row here first.
- **Nothing is shared between a variation and the live site except content and public assets.** Each variation has its own stylesheet under `src/styles/variants/` and its own layout under `src/layouts/variants/`. `src/styles/global.css`, `src/layouts/MainLayout.astro` and the live `src/pages/index.astro` belong to production and are not to be touched while working on a variation. That separation is the point: a variation must be changeable without any risk to `/`. The live page's only departure from `main` is the switcher at its foot, and that is temporary.
- **Variations are noindex, always.** Their layouts hard-code `<meta name="robots" content="noindex, nofollow" />`, they are excluded from `public/sitemap.xml`, and each route is listed under `Disallow:` in `public/robots.txt`. No canonical tag either, so a stray crawl cannot fold a variation into `/`.
- **The switcher.** `src/components/variants/VariantSwitcher.astro` is a fixed pill at the foot of the live page and every variation, listing Live plus each variation. It carries its own scoped styles and uses no design tokens, so it renders identically on top of any design and can never be the reason two variations differ. It rides along on `/` because the whole set lives on the `redesign` branch for review; that is the one non-production thing on the live page, and it comes off before anything ships (delete the import and the `<VariantSwitcher current="live" />` at the foot of `src/pages/index.astro`).
- **An in-page link inside a variation never leaves it.** A variation is one page, so a plain `#anchor` is enough and is what v1 uses since the final version landed on 2026-09-11: it neither reloads the page nor drops the reviewer onto the live one. `Logo` and `Footer` still accept a `base` prop for the variations that build their anchors from it. Links that genuinely leave a variation (legal, `for-advisors`, mail) are root-relative or `mailto:`, never absolute: canonical URLs come from `astro.config.mjs`.
- **Starting a new variation.** Set the row in `variants.ts` to `ready`, add `src/styles/variants/<v>.css` and `src/layouts/variants/<V>Layout.astro` (copy the closest existing pair), then replace `src/pages/<v>/index.astro`. Never point two variations at one stylesheet. Two variations with identical stylesheets are served one shared CSS asset because Vite hashes by content; the moment one changes it gets its own. The source files are separate regardless, which is what matters.
- **Copy is the client's, in every variation.** A variation changes layout and visual system, not words. See rule 7 below.

## Design system

Each design has one source of truth for visual style. Use it. Do not invent new tokens, sizes or button variants inline.

- **Live system lives in `src/styles/global.css`.** All tokens (colour, type, spacing), atoms (buttons, eyebrows, badges, inputs, avatars, dividers, links) and molecules (step card, plan card, feature card, metric row, post card, author chip, form field, mobile menu link, case stat, case quote card, testimonial, breadcrumb, author panel) are defined there. It is the system behind `/`, the legal pages, the blog, `for-advisors` and the deck, and it is what `/design-system` documents.
- **The v1 system lives in `src/styles/variants/v1.css`,** loaded by `/v1` alone. It is the client's final v1, delivered 2026-09-11 as one flattened self-contained page (`client_resources/compound-health-v1-new.html`, which revised the first drop the same day) and applied to the project that day: the stylesheet is that file's `<style>` block, and its body is split between `V1Layout` (nav, mobile menu, footer, the intro, Lenis, the bar and the reveal observer) and `src/pages/v1/index.astro` (the sections and their own scripts). Three changes were made in the port and no others: the two Aeonik faces and the five photographs are linked from `public/` rather than embedded as base64, the links that leave the page are root-relative rather than absolute, and the page-ground rule excludes `[data-variant-switcher]` so it cannot paint over the switcher pill. **A new drop is ported by regenerating all three files from it, not by hand-patching them**, so nothing can drift: checksum it against the one in place first, because a re-download arrives under a new name and is not a revision. Rules 3 to 6 below describe that system, not the live one. It is not documented under `/design-system` yet; when v1 is chosen, its documentation moves there in the same pass.
- **The v2 system lives in `src/styles/variants/v2.css`,** loaded by `/v2` alone, built 2026-09-07. It follows [joindawn.com](https://joindawn.com): their layouts, palette, type, motion and interactions, with the client's copy unchanged. Nothing is shared with v1 beyond the `Logo` component and the switcher.
  1. **The brand green on Dawn's scale.** Cream `#F3F5EE`, sand `#E7EBDD`, peach `#CFDDB8`, green `#7DAE4E`, amber `#A9C95B`, gold `#D8DE7A`, lime `#C6D24C`, burnt `#6E9E3E`, cocoa `#2F4A1E`, ink `#12200F` (which is also the dark ground), plus a deep green pair for the closing card. Text is ink or cream; muted text is ink at 70%. The token names are Dawn's, because the structure is; the values are the brand's.
  2. **Type.** Source Serif 4 (regular, with italic for `em`) for every heading and figure; Figtree for reading, labels and buttons. Two faces and no third: the wordmark is drawn, so Lato came out of the font request and `--font-logo` with it (2026-09-11). Eyebrows are 12px caps letterspaced 0.2em with no box.
  3. **The page opens dark and the sun comes up.** The hero is two rounded cards on the ink ground inside a 0.5rem inset: the warm gradient card carries the headline, the photo card carries the standfirst and actions, and one circle spans both, dotted on the left and solid on the right. Then `.scroller` (260vh) pins a stage in which a gradient arc draws itself around a dotted ring as the reader scrolls (GSAP ScrollTrigger, scrubbed) with the "process" head in burnt orange, and `.sunrise` (a fixed-height gradient from ink through orange and yellow to cream) hands the page to the light ground, with the three step cards sitting at its foot.
  4. **Stacked sections with rounded feet.** Every section from the sunrise on is `.stack`: a 5rem bottom radius, pulled up under the section above by the same amount, with descending z-index classes (`.z7` down to `.z1`) so each lies over the next. Grounds alternate cream, sand, the brown gradient (`.bg-brown.is-dark`), sand with a silk sheen (`.silk`), cream.
  5. **Cards, pills, discs.** `.card` is cream with a 1px white edge and a 1.25rem radius; `.is-lift` raises it on hover. Every primary action is `.btn-primary`, Dawn's radial orange-to-gold pill, and every button scales to 0.95 on hover. `.tag-brand` is the gradient chip. `.disc` is the peach icon circle. `.pill-past` (dim, dashed) and `.pill-glow` (gradient, glowing, blurred in by scroll) are Dawn's past-and-future contrast; on v2 they carry the "what you get" standfirst's own words.
  6. **Figures.** `.chat` in the wide feature card is a thread of gradient bubbles carrying the sentence's three verbs. `#disciplines` is a tablist of gradient pills driving one cream card with chips lifted from the discipline's sentence. `#audiences` is the coverflow carousel of the four audience cards (arrows, keys, swipe). The closing `.sky` card is a CSS sky with drifting clouds and a second scroll-drawn arc; the form sits beneath it on cream. The footer is Dawn's plain dark block, written in `V2Layout`.
  7. **Motion.** Arcs and the stage copy are scrubbed by scroll; everything else is a one-shot `.reveal`. The bar hides on the way down, returns on the way up, frosts once scrolled, and turns ink over the light ground via the `[data-nav-light]` sentinel. Reduced motion draws the arcs in full and disables the scrubs.
  7b. **The handover into the sunrise is a dissolve, not an edge** (client's call, 2026-09-11). `.sunrise` is pulled up 60vh over the pinned circle stage and its top is opaque ink, so it swept up over live content and cut it: the reader was left, for the last 60vh of the pin, looking at an arc and a standfirst sliced through by a hard horizontal line. The line itself was never the problem, ink meeting ink being invisible; being drawn across was. Two things fix it and both are needed. `.scroller::after` is a 26vh strip riding immediately above that edge, transparent to ink, taking the stage down to the ground before the edge reaches it; it is in document coordinates, so its `bottom: 60vh` is the sunrise's own `margin-top` and the two move together, and it needs `z-index: 3` to clear `.scroller-copy`'s 2 while staying under `.sunrise`. And the scrubbed timeline now retires the ring with the copy (both out by 0.9 of the scroller), so at the moment the pin releases there is nothing left on the stage at all. The strip is what carries reduced motion, where the timeline never runs.
  8. **One palette, and it is Sage** (client's call, 2026-09-11). v2 carried three complete palettes over one structure, switchable from a pill; Dawn (the reference's own orange and cocoa) and Dusk (midnight and lavender) are gone, and Sage, the brand green, is folded into `:root` as the only one. What went with them: the two `html[data-theme]` blocks, `V2ThemeSwitcher.astro`, the pre-paint theme script and its `?theme=` and `localStorage` handling in `V2Layout`, and `--grad-text-soft` with `.text-grad-soft`, which was the last hardcoded Dawn colour in the file and was on a class nothing used. The tokenisation the themes forced is worth keeping and is why the swap was a palette edit and nothing else: every colour is a token, the rgb triplets for translucent uses included (`--ink-rgb`, `--cream-rgb`, `--glow-rgb`, `--tint-rgb`), so are the stops of the brown, deep and sunrise gradients (`--brown-*`, `--deep-*`, `--sun-*`), and the SVG gradient stops in the page take their `stop-color` from those tokens. Keep it that way: a colour added to v2 is added as a token.
  9. **The logo is the 2026-09-11 lockup, and it is drawn** (client's call). `V2Logo.astro` carries the client's `logo-new.svg` inline: the mark, the wordmark and the space between them are one drawing on one viewBox, tight to the artwork, so the stylesheet sets a height (22px in the bar, 24 in the footer) and nothing else, and no proportion inside the lockup can drift. `Logo.astro` is untouched and still serves v3; v1 took a drawn lockup of its own in `V1Logo.astro` with the final v1 on 2026-09-11. Three things follow from it. The wordmark is paths, so v2 loads two faces instead of three. The mark and the wordmark are separate groups filled with `currentColor` over a `color` the stylesheet sets, which is how the bar keeps inverting: green mark and ink wordmark over the hero's light card, green mark and cream wordmark once the ground is dark, `--burnt` over cream. And below 480px the bar shows the mark alone, from a second drawing on its own tight viewBox, because a viewBox cannot be set from CSS: the full lockup is 216px wide against a bar that also has to hold the action pill and the burger, and at 390px it pushed the pill into wrapping to two lines. The pill is `flex-shrink: 0` and `white-space: nowrap` now, so it can never do that again. Measured at 320, 360, 390, 430, 480, 768, 1024 and 1440: the pill's right edge stands 64px inside the bar at every one.
- **Documentation lives at `/design-system`.** Three routes, all noindex via `DesignSystemLayout`:
  - `/design-system` — overview and working rules.
  - `/design-system/atoms` — colour, typography, spacing, radii, buttons, badges, eyebrows, dots, avatars, dividers, inputs, links, motion.
  - `/design-system/molecules` — every reusable block on the site, with code snippets.
- **Methodology.** Atomic design (atoms → molecules → organisms → templates → pages) combined with [Finsweet Client-First](https://finsweet.com/client-first) naming. Class names are lowercase, hyphen-separated, with `is-active` / `is-open` for state and modifier classes like `.is-good`, `.is-warn`, `.tone-sage` for variants.
- **Rules.**
  1. Every visual change starts in the stylesheet of the design you are working in: `global.css` for the live site, `src/styles/variants/<v>.css` for a variation. If a token, atom or molecule does not exist for what you need, add it before using it. Never edit `global.css` to serve a variation.
  2. Do not inline colours, sizes or backgrounds on elements. Position values that come from data (e.g. `.metric-lead style="width:82%"` and `.metric-mark style="left:82%"`) are the only legitimate use of inline `style`. Colours always come from a class.
  3. **One white ground, and the colour arrives in the photographs (v1).** The page runs on `--warm-white`, which is plain white in this system, from the bar to the footer. Text and surfaces come from superpower.com's zinc ramp; the accent is the client's own rust (`--sage` is an alias of `--tone-rust`), and the brand tones (rust, umber, bronze, moss, sand) carry every tint, every data figure and every gradient. Two photographic cards open and close the page, `.hero-card` and `.closer-card`, built on the same shape; `.plans` is the one dark section, ink with the rust light rising from its lower left; the feature panels take a tone through `.feat-visual.tone-*`. Anything that sits over the fixed footer has to be opaque, which is what the `body > section, body > div, body > .rule` ground rule is for. Do not add a background band to a section that has not got one.
  4. **Type is Aeonik on superpower.com's scale (v1).** Two faces and no third, Regular for reading and Medium (500) for titles, self-hosted at `public/fonts/`. The root size is fluid, about 15px at 1440 and 16px on phones, and every size, leading and tracking in the file resolves to a `--fs-*`, `--lh-*` and `--ls-*` tier in the type block at the top. Retune the page from that block; never write a raw font-size.
  5. **Section heads use `.s-head` (v1).** Chip, title, standfirst, and an optional `.s-head-action` pill that carries a real destination. `.s-label`, the older uppercase label, is what the live system uses on the home, legal, blog and deck pages.
  6. **Every figure is a different machine (v1).** The feature mock-ups (`.fm-*`: a score card, a care team, a biomarker chart, a protocol list, a message thread) play once when their card comes into view. The disciplines (`.prod-*`) are a tablist that advances itself every 7s, the countdown drawn as the ring around the open tab's icon so the ring and the switch cannot drift apart; keyboard focus and leaving the viewport stop it, hovering does not. The credibility row at the foot of the hero is a marquee on phones and a static row above 900px. Every label inside a figure is lifted verbatim from copy already in that section: a figure illustrates copy, it never introduces new copy.
  7. **Copy is the client's.** Do not rewrite, shorten, add or remove marketing copy, headings or CTA labels while doing visual work. If a layout needs different words, raise it rather than changing them.
  8. When you add a new atom or molecule to `global.css`, add a documentation block to the corresponding `/design-system` page in the same commit. A variation's stylesheet is not documented there until that variation is chosen.
  9. All `/design-system/*` routes must stay noindex and out of `public/sitemap.xml`.
- **The bar and the footer are the two set pieces (v1).** The bar is transparent over the top of the page and collapses into a blurred black pill once scrolled. Every value that differs between the two states is a custom property on `.main-nav` (`--nav-pad-y`, `--nav-inner-max`, `--nav-pill-a`, `--nav-blur`, `--nav-ink`, `--nav-cta-*`, `--ham-*`) and GSAP tweens them as a set, so the bar reshapes, recolours and blurs in one movement; a change of mind mid-tween retargets rather than restarting, and a little hysteresis at the threshold stops it flickering. Below 900px it stays at rest and the nine-dot button opens the full-screen menu. The footer is fixed at the foot of the window behind the page, and the closing card travels over it and slides away to uncover it: the page reserves exactly the footer's height in `--footer-h`, measured by the script in the layout. Changing the footer's height changes nothing else, which is the point of measuring it.
- **The lockup is the client's own file (v1).** `V1Logo.astro` carries it inline: mark and wordmark are one drawing on one viewBox, the wordmark on `currentColor` so the bar can invert over the hero photograph, the mark on `--logo-icon` so it can hold the brand rust while the wordmark changes around it. - **The v3 system lives in `src/styles/variants/v3.css`,** loaded by `/v3` alone, built 2026-09-10. It follows [lassie.ai](https://www.lassie.ai/): their layouts, palette, type, motion and interactions, with the client's copy unchanged. Nothing is shared with v1 or v2 beyond the `Logo` component and the switcher.
  1. **One ground, no bands.** `--bg-primary` (`#F9F8F5`) runs the whole page. Sections are separated by air alone, 100px rising to 200px at desktop, never by a change of background.   3. **Two faces, and only two** (client's call, 2026-09-11). Newsreader at weight 350 stands in for ABC Marist, the reference's commercial display serif: a variable axis so the display sits on 350 exactly, a low x-height against a generous cap, and a true italic. Numbers still align, through `font-variant-numeric: tabular-nums` where they are read in a column. Emphasis inside a heading is the serif italic, never a weight or a colour.
  3b. **No elastic overscroll** (2026-09-11). `overscroll-behavior-y: none` on `html`, so the page does not bounce at either end. The deck and the orbit are pinned stages and a rubber band drags a pinned composition with it and lets go, which reads as the layout coming loose. The block axis only: the shorthand would take the horizontal overscroll with it, and the two-finger swipe back along with that.
  4. **No shadows, no borders, no hairlines in the layout.** Elevation is radius and fill. Two shadow strings exist in the whole system and one of them is the focus ring. Form controls are fills rather than outlines. Focus is a design element: 2px `#42B5DC` plus a 3px halo, on everything.
  4b. **One radius ladder, five steps, and only the last one grows** (2026-09-11). Because radius is the only thing carrying elevation, it is the one value on the page that cannot be improvised, and it was: eleven distinct radii for five ideas, two overlapping token sets, a dead `--r-panel`, a `--r-tile` that duplicated `--r-chrome`, and four different desktop jumps on things that step together. Nothing is authored outside that block. The four exceptions are stated in the block and are the only ones: `999px` on a stem or the chevron, `50%` on a disc, `1px` on the burger's bars, and `0` on a thing that has deliberately given up its box, which is `.disc.is-bare` inside a `.static-art` that already paints the frame. Two consequences worth not undoing. So under 768 the facts are divided by horizontal rules rather than vertical ones, each row of each list carries a rule above it, the figure comes down to 3.2rem so it stops competing with the passage's own opening line, and the gap that opens a new group (6.4rem) is three times the gap between two rows of the same list. From 768 up the two columns do that work themselves and every one of those rules is switched off.
     - **Four attempts, and why the first three failed.** An accordion of seven identical closed bars in a tall column beside a short card left the right half of the section empty. Four white cards and a three-up of principles balanced it but read as four rows of the same weight with nothing for the eye to hold. A dark photograph band carrying the three facts, over two numbered columns, gave it an anchor but the lists still read as a directory. The passage works because the content is an argument and was being laid out as a grid. Its own asset, `partners-band.webp`, was cut from `quad-photo-a` and then deleted with the layout that used it; the recipe is in `docs/v3-art-brief.md` if a band is ever wanted again.
     - **The passage was cut back on 2026-09-11**, because the client's judgement was that nobody would read it at full length. The section went from 331 words to 181. Each audience kept its first sentence and lost its second: the first is the brief's own `Who they are` column, the second described how the arrangement works, which is exactly what the three terms under it say. The `What we delivered` list, four bullets from the one delivered session, came out entirely; its action, `Talk to us about a program`, stayed. Both cuts are the client's own copy and both are one revert away: the sentences are in `f477f8a` and in `client_resources/`.
     - **The two lead-in lines are the only words on this page that are not the client's.** `Who this is for:` and `On what terms:` are structural connective tissue rather than marketing copy, they came with the layout the client picked, and they are cheap to change. One sentence in the section has no source in either client document: `One program across generations`, the Family offices line, which was written in the 2026-09-04 rebuild. The brief has no such audience; it puts family offices inside Wealth firms. Worth confirming with the client rather than inheriting.
  13. **The form is one question at a time, on the closing card** (client's call, 2026-09-11). The standalone `Get access` section was removed and its form moved onto the closing photograph, where the email capsule used to be; `#joinwaitlist` now sits on `.cta-band`, so every link that pointed at the old section (the bar, the three membership buttons, the partner button) lands on the card with nothing to re-point. Five steps: **I am**, first and last name, email, tier or organization name, and the optional referring advisor or reach. The last step carries `Skip`, which clears the optional field and submits.
     - **The controller owns the sequencing and nothing else.** `.sf-*` in `v3.css` and the last script block in the page move between steps, count them and validate the one in front so the reader is told at the question. Every value, the audience routing, the real validation and the POST stay in the form script above it, whose ids (`wf-fname`, `wf-email`, `wf-tier`, `wfSubmit`, `waitlistSuccess` and the rest), routing tags and endpoint are the live form's and are not renamed.
     - **It is additive.** The steps are in flow and all five are readable with no JavaScript; the controller adds `.is-stepped` to `#sfWindow` to take ownership. It writes two values: the window's height, because the steps are stacked in one place and nothing else can know it, and the progress bar's width, which is the step number.
     - **The surface is glass on a photograph.** Every colour on the panel is an alpha of white or of stone, never a fixed grey, so it holds over any frame that lands in that slot. The listbox is the exception and is solid white: a menu read word by word does not sit on a picture. `.btn` sets its own `display`, so a hidden action needs `.sf-actions [hidden] { display: none }` or it stands in the row anyway. The actions row reads left to right in the order it is used, the action first: every label, field and note on the panel starts at the same edge, and a button pushed to the far side was the only thing not standing on it (client's call, 2026-09-11). A step's own rhythm is a flex `gap` rather than the fields' margins, because a flex gap skips a `display:none` child and the two steps that carry a hidden partner field were otherwise 16px taller than the rest. And a disabled button neither moves nor shows its icon: it still matches `:hover`, and the disabled fill is translucent, so the arrow slid out and then read through the label while the form was submitting.
     - **The card grew a floor instead of a fixed height.** `.cta-card` is `min-height` at each breakpoint (46.5rem, 64rem, 80rem) so a tall step is never clipped, and the mark gave up a third of its size to make room.

## Blog system

The blog is pre-launch. Every route under `/blog`, `/blog/category/*` and `/authors/*` is currently **Noindex** via `BlogLayout`'s default `noindex={true}`. None of these routes appear in `public/sitemap.xml`.

- **Content lives in `src/data/blog.ts`.** This file holds typed `Author`, `Category` and `Post` collections. To add or edit a post, author or category, edit this file. Do not introduce a separate CMS layer without a discussion.
- **Slugs are the URL.** Author slugs are `first-lastname`. Category slugs are short, lowercased nouns. Post slugs are kebab-case.
- **Authoring posts.** `bodyHtml` is raw HTML. Stick to `<h2>` and `<p>`. The post body inherits the `.prose` styles in `global.css`.
- **American English** in all blog copy, per project standing instructions.
- **When launching the blog publicly:** pass `noindex={false}` on the relevant `BlogLayout` instances (or change the layout default), add each newly-indexed route to `public/sitemap.xml`, and flip its row in `PAGES.xlsx` from `Noindex` to `Indexed`.
