# CLAUDE.md — Compound Health Website

Instructions for any agent (Claude or otherwise) working in this repository. Read this file at the start of every session before making changes.

## Project at a glance

- **Site name:** Compound Health
- **Production URL:** https://compoundhealth.io
- **Stack:** Astro 6 (static), vanilla CSS, GSAP for motion, Lenis for smooth scroll
- **Hosting:** static output from `npm run build` (`dist/`)
- **Folder location:** Google Drive shared folder (`Longevity Folder - G and A/Marketing & Presentations (external)/Website/compound-health`). Files saved here sync to Drive.

## The shape of this project

The client designs the site and delivers it as finished HTML: one self-contained file per page, carrying the whole design system, the fonts and the photographs inline. This repository is the Astro tree those files are split back into. So the source of truth for everything visual is `client_resources/final_version/`, not `src/`.

That has one consequence that governs almost every rule below: **`src/styles/global.css`, `src/layouts/SiteLayout.astro`, `src/components/Logo.astro`, `src/components/Footer.astro` and the three pages are generated files.** Do not edit them by hand. A new drop is ported by running `scripts/port-drop.py` against it, which regenerates every one of them, so nothing can drift from what was delivered. Hand-patch one of them and the next drop silently reverts your change.

## Standing operating instructions

1. **Always load full project context before doing work.** Before any edit, list `src/pages/`, open the relevant `.astro` files, and re-read this CLAUDE.md and `PAGES.xlsx`. Do not rely on assumed state from a prior session — the repo is the source of truth.
2. **Do not hand-edit a generated file.** See "The shape of this project" above. If a visual change is genuinely needed and cannot wait for a drop, say so rather than editing `global.css`: the change will be lost.
3. **`PAGES.xlsx` is the page inventory.** Every page on the site is listed there with its name, URL, status (Live / Draft / Archived), indexing (Indexed / Noindex), layout, source file and last updated. Update it whenever a page is added, removed, renamed, or its indexing changes.
4. **`public/sitemap.xml` mirrors the indexed pages from `PAGES.xlsx`.** When a new indexed page ships, add it with today's `<lastmod>`. When a page is removed or switched to noindex, remove it. Never include a noindex route in the sitemap.
5. **Indexing rule.** A page is indexed by default. `SiteLayout` writes a canonical and no robots meta. To make a page private, use `MainLayout` with `noindex={true}` or add `<meta name="robots" content="noindex, nofollow" />`, and keep it out of the sitemap.
6. **Canonical URLs come from `astro.config.mjs` (`site:`).** Do not hardcode absolute URLs in templates. The client's drops use absolute `https://compoundhealth.io/...` links; the port rewrites them root-relative.
7. **American English** in all prose. Compound Health is US-based and serves US clients, so the entire site uses American spelling (optimize, color, personalized, program, advisor). Legal copy already uses US spelling.
8. **No em dashes** in copy.
9. **Copy is the client's.** Do not rewrite, shorten, add or remove marketing copy, headings or CTA labels. If a layout needs different words, raise it rather than changing them.
10. **Name no other website.** Not in code, comments, commit messages, docs, this file or `PAGES.xlsx`. Describe a design in its own terms: "a transparent bar that collapses into a blurred pill", never "after" another site or "that site's" values. Everything here is public, and comments in markup and scripts ship in the page source. The port enforces this for the generated tree against the term list in `client_resources/reference-terms.txt`, which is not committed; extend that list rather than writing a term into the repo.

## Porting a new drop

The client sends new HTML. Do this, in order:

1. **Checksum it against what is in place.** `md5 client_resources/final_version/*.html` and compare. A re-download arrives under a new name and is not a revision; only a differing checksum is.
2. Put the new files in `client_resources/final_version/`, keeping the filenames the script expects.
3. **If the drop embeds an asset that is not already in `public/`, the script stops and names it.** Extract it, save it under `public/` and run again. Nothing is written to `public/` automatically: an unrecognised asset is a decision, not a step.
4. `python3 scripts/port-drop.py`
5. `npm run build` and check it compiles clean, with no unresolved-asset warnings.
5b. `python3 scripts/build-llms-full.py`. The page copy changes with the drop, and a stale `llms-full.txt` is worse than none. `public/llms.txt` is hand-written and does not regenerate.
6. Diff the generated files and read what changed, so you know what the client actually revised.
7. Update `PAGES.xlsx` and `public/sitemap.xml` if any page was added, removed or renamed.
8. Commit, referencing what the drop changed.

The script makes ten changes to the drop and no others. They are listed in its docstring; the three worth knowing here are that every comment the drop carries is removed, so none of the designer's working notes reach the page source, and that fonts, photographs and icons are linked from `public/` rather than embedded as base64, and that the legal pages' section anchors take a `base` of `/` so they reach the home page (the drop leaves bare `#how` hashes in the legal footer, which go nowhere there).

## The design system

`src/styles/global.css` is the whole visual system: tokens, atoms and molecules. It is the drop's own `<style>` block.

- **One gradient the length of the page, and the colour arrives in it and in the photographs.** The home page has no white ground (design revision 29): one layer on the body, under every section and over the fixed footer, runs from white under the hero through night blue and moss tints that alternate down the page, deep enough to read as colour at a glance, and back to white at the close; across it the left, where the copy sits, is lighter than the right. The sections are clear over it, except the dark `.plans`. The layer ends where the body ends, and the close's margin that reserves the footer's room falls outside the body, so the footer is still uncovered. On it the quiet grey `--mid` is one step darker (`--zinc-600`), to keep body copy over 4.5:1. Only the home page takes it, scoped by `body:has(> .closer)`: the legal pages and the 404 keep white, because their footer is in the flow and the layer would cover it. Text and surfaces come from the zinc ramp; the brand runs on two cool families, moss and night blue, which carry every tint, every data figure and every gradient. The accent is the light moss (`--sage` is an alias of `--tone-moss-light`); night blue (`--tone-night`, `--tone-blue-deep`, `--tone-blue`, `--tone-blue-light`, `--tone-blue-pale`, `--tone-blue-tint`) is the hero photograph's sky. The drop still delivers warm tones (rust, umber, bronze, taupe, olive, sand); design revision 16 maps every use onto moss and night blue as it ports, and stops the port if one survives. Do not bring a warm tone back. `.hero-card` opens the page as a photograph filling the first screen edge to edge, with no inset and no rounded corners, and its copy (headline, standfirst, actions) in one column resting on the photograph's foot at the bottom left, on the dark of the sky (design revision 28). The copy cannot move right: she fills the right half of the frame and white type on her lit neck does not read. The page closes on a statement instead: `.closer` centres its heading, line and action on the white ground, with the photograph beneath as a 21:9 panorama in the content column and nothing laid over it, and the section ends on the photograph's lower edge (no padding under it), so the photograph itself uncovers the footer; `.plans` is the one dark section; the feature panels take a tone through `.feat-visual.tone-*`. Anything over the fixed footer has to be opaque, which is what the `body > section, body > div, body > .rule` ground rule is for.
- **Type is Aeonik for text and Inter Display for headings.** Aeonik Regular for reading and Medium (500) for labels and the figures' data; the headings (`h1` to `h6`, `.step-title`, `.plan-name`, `.case-num`, `.mobile-nav-link`) in Inter Display SemiBold (600) through `--font-head`, design revision 30. The display cut is drawn tight for large sizes, so with the tiers' negative tracking the titles stay dense and heavy. Three faces and no fourth, all self-hosted at `public/fonts/`. The root is a fixed 16px, so rem spacing does not move with the window; the headings scale instead, each through `clamp()` between a phone and a 1440px desktop, tightening their leading and tracking as they grow. Every size, leading and tracking resolves to a `--fs-*`, `--lh-*` and `--ls-*` tier in the type block at the top of the file, which `scripts/design_revisions.py` writes in place of the drop's own.
- **The bar and the footer are the two set pieces.** The bar is one glass island of fixed width (960px wherever it fits), square at the corners, floating over the page, with the lockup on the left and the four section links and the moss "Get access" action on the right, the action last. `.main-nav` is only the frame that centres it and lets clicks through; `.nav-inner` is the island. It never changes on scroll, and it has no outline and no shadow (the drop sets every `box-shadow` to none, site-wide). Its ink is white throughout, logo mark included; only the glass changes, by what is under it, read off the page at seven points along its middle by the script in the layout (a photograph counts as dark unless marked `data-ground="light"`, as the two sky photographs are, a gradient by its first stop). The brightest point decides, since the ink is white: one light card under the links turns the island dark. Over the hero, the dark feature panels, `.plans` and the closing card it is the hero's own glass button, 10% white over a 32px blur; over the white page it is deep blue glass, the hero photograph's night blue (#0a1a26) at 88% over a 24px blur; any thinner and the white page lifts it to slate grey. Link hover turns the ink pale night blue (`--tone-blue-pale`), with no fill. Below 900px the island runs the width of the screen less a gutter, and the menu button inside it, two lines that cross into an X, opens the full-screen menu. The island, and the edge-to-edge hero under it, are design revisions in `scripts/design_revisions.py`, applied by the port on top of the drop. The footer is fixed at the foot of the window behind the page, and the closing section travels over it and slides away to uncover it: the page reserves exactly the footer's height in `--footer-h`, measured by the script in the layout.
- **From 901px, What you get is a stack.** The six figures stick under the bar one after another at the same top: each enters the screen only once the one before has settled and held for 12vh, and as it rises the one beneath only shrinks, about its centre to 90%, so it ends wholly behind the new one with no edge or fade showing. One eased progress per hand-over drives everything: the figure's shrink (`--recede`) and the copy on the left (`--in`, `--out`), which lifts away by the midpoint of the travel and rises in after it, so the two copies never share the screen. The last figure holds for 30vh, then leaves. The script in the layout lays it on (`.feat-grid.is-stacked`), marks `.is-current` and `.is-covered`, sets `--recede`, `--in` and `--out`, and starts each mock-up as it rises, because the articles take `display: contents` so the figures can share one sticky containing block, and the page's own observer cannot see a box-less article. Sticky depends on no ancestor clipping or scrolling: do not put `overflow: hidden` on `body`, `.features` or `.inner`.
- **On phones, and without the script, What you get is an index of rows.** Each of the six features is one row, ruled off by hairlines: its number (a CSS counter, moss, so the markup carries no new copy), its title at h4 and its description at reading size on the left, its figure in a 16:10 tinted panel on the right; below 900px the figure drops under the copy. The drop still delivers a two-column grid of tall panels with the text beneath; `scripts/design_revisions.py` re-lays it, without touching the markup.
- **Every figure is a field.** Each figure is one flat tone (`.feat-visual.tone-*`, and `.prod-panel` for the disciplines) with its content set straight on the colour in white: no gradient, no blurred light, no white card floating on it, no shadow. The heading sits at the top as a quiet label and the data is anchored to the foot. Design revision 17 lays this on, with the shared atoms every figure composes from; each figure is then redesigned on top of it in its own revision (18: the Healthspan score, the score at display size beside its three counts, the bar divided by the counts; 19: ApoB, the name at display size and one heavy line over the range band, only the latest reading marked; 20: Your protocol, each item a headline-size row under a rule, its category a small label above; 21 to 24: the care team, the clinical record as a ledger, the concierge thread set as type rather than bubbles, and the three devices in the disciplines panel). Do not bring back the floating card.
- **Every figure is a different machine.** The feature mock-ups (`.fm-*`: a score card, a care team, a biomarker chart, a protocol list, a message thread) play once when their card comes into view. The disciplines (`.prod-*`) are a tablist that advances itself every 7s, the countdown drawn as the ring around the open tab's icon so the ring and the switch cannot drift apart; keyboard focus and leaving the viewport stop it, hovering does not. Its panes cross rather than swap and build in one choreography on three curves (`--ease-arrive`, `--ease-leave`, `--ease-turn`), design revision 25: entries are one-shot animations keyed on `.is-active`, nothing loops, and nothing fades out before a switch. The 500 count is a CSS `@property` counter on the ring's own curve, so the drop's counting script finds no arc animation and stands idle. Advanced therapies is a gate (revision 26), read top to bottom: the two conditions with square check boxes, then a stack whose bands are named by the section's own words ("Clinical care" and "Diagnostics and screening" from the tab titles, and above them the add-on layer, "Hormones, peptides, and regenerative therapies", from the tab's copy). On entry the conditions check in turn and only then does the add-on slot fill and settle onto the stack. The credibility row at the foot of the hero is a marquee on phones and a static row above 900px. Every label inside a figure is lifted verbatim from copy already in that section: a figure illustrates copy, it never introduces new copy.
- **Solid moss is primary; secondary is quieter.** Every solid button is the brand moss (`--tone-moss-light`) with the deeper `--tone-moss` on hover, over the photographs as on the white page. A secondary action is an outline on the white page (zinc-300) and a plain text link on the dark grounds (the hero, `.plans` and its cards): white words, no fill, outline or blur, underlined on hover. No action carries an arrow: the port strips the trailing arrow glyph from every button and link label and the drawn arrow from the form's submit and the menu's action, leaving the words as delivered. The hand-written 404 follows the same rule.
- **Every corner is square.** No element carries a radius: buttons, chips, tags, inputs, cards, panels, the form, the figures, the bar, the closing panorama, and the status dots and avatars too. The drop still delivers pills and rounded corners; `scripts/design_revisions.py` sets every `border-radius` in the stylesheet, its own block included, to 0 as it ports, and stops the port if one survives, so a new drop lands square too. The skip link's radius lives in the layout template in `scripts/port-drop.py` and is 0 as well.
- **Section heads use `.s-head`:** chip, title, standfirst, and an optional `.s-head-action` pill carrying a real destination.

## Launch scaffolding

The drop is a design, so it carries none of this and `scripts/port-drop.py` adds it (change 7 in its docstring). Do not hand-edit it into `SiteLayout.astro`: edit the script's template.

- **Canonicals have no trailing slash**, matching `sitemap.xml` and the URLs already indexed, even though the build emits directories. Which form the host actually serves is still an open hosting decision; this only stops the two files in the repo contradicting each other. `MainLayout` does the same.
- **`noindex` and the canonical are one prop.** `SiteLayout`'s `noindex` emits the robots meta and suppresses the canonical, because a noindex page with a self-referencing canonical tells a crawler to index the URL it was just told to ignore.
- **`Organization` JSON-LD on the home page alone.** `sameAs` is deliberately absent: no social profile has been supplied. Add the real URLs when there are any; a guessed profile is worse than none.
- **The skip link** is the first tab stop on every page, and lands on `id="main"`: the hero section on the home page, `<main>` on the legal pages, `.nf` on the 404, `.deck-hero` on the unrouted for-advisors draft. The page has no `<main>` wrapper of its own because every section must stay a body child for the ground rule that keeps the fixed footer covered.
- **The 404 makes the footer static.** `global.css` fixes the footer and has only `.closer` reserve room for it, so any page without a closing card has to override that, as the legal pages do.

Still open and not repo work: preview-deployment `noindex`, www against non-www, the trailing-slash decision at the host, HTTPS and HSTS, security headers, analytics, form anti-spam and rate limiting, CRM and lead alerting, and a DPA for the personal data the form writes into Google Sheets.

## The legacy system

`src/styles/legacy.css` is the design system this one replaced, and `src/layouts/MainLayout.astro` is its layout. Between them they served exactly one page, `/for-advisors`, a noindex draft that was never redesigned.

Since **2026-09-14** that route redirects to the home page, declared in `astro.config.mjs`. The page source is kept at `src/pages/_for-advisors.astro`: the leading underscore takes it out of Astro routing, so the draft stays in the tree without answering a request and without colliding with the redirect. Nothing routes `MainLayout` any more, so neither it nor `legacy.css` is emitted into `dist/`. Both are kept for the redesign, and the draft is restored by renaming the file back and removing the redirect.

A static build emits the redirect as `dist/for-advisors/index.html`, a meta-refresh document carrying `noindex` and a canonical at the home page rather than a 301. The real 301 belongs at the host, with the www and trailing-slash decisions that are still open.

The home page bar and footer both still link to `/for-advisors`, so those links now bounce back to the home page. Both are generated files: the fix is in `scripts/port-drop.py`, which already rewrites that href, or in the next client drop. Do not hand-patch it into `SiteLayout.astro` or `Footer.astro`.

Do not build anything new on the legacy system, and do not merge it into `global.css`. When `/for-advisors` is redesigned, `legacy.css` and `MainLayout.astro` go with it and `src/styles/` holds one file again.
